# Effectus v0.5.0

These notes describe the v0.5.0 release line, not every later working-tree change.
Use the current [command reference](../COMMANDS.md) and [runtime guarantees](../GUARANTEES.md) for deployment instructions.
Local remediation evidence does not prove that a published tag contains those later changes.

Effectus v0.5.0 is a correctness and validation release. It adds no product feature and no public API.

The single production execution path is unchanged:

`bundle.SourceBundle` → `compiler.CompileChecked` → `ir.Checked` → `runtime.Generation` → `runtime.Engine.Execute`

## Product surface

The v0.4.0 limits remain in force, and repository guardrails still check them:

- 11 product package domains.
- 16 public Go packages, including generated and compatibility packages.
- 3 immediate examples.
- 18 visible Just recipes.
- 1 Go module.

This release adds no public package, protobuf message, execution state, or Just recipe.

## Correctness changes

The audited remediation resolved 32 findings. The changes that alter observable behavior are:

- Predicate calls without an implementation are rejected before executable generation, including unreachable calls.
- `ir.NormalizeValue` owns bounded closed values recursively and rejects cycles, excess depth, and unsupported forms with a path.
- Checked bytes literals resolve to padded base64 in both resolvers, including the empty value. Existing nonempty stored identities are preserved.
- Observed dispatch disposition persists independently of caller cancellation, within a bounded window and remaining authority.
- Malformed executor outcomes become unknown outcomes rather than assumed failures.
- An unknown outcome may be retried only under a checked `SINK_GUARANTEED` contract within its checked attempt cap.
- Wrapped cancellation and deadline errors stay transient during historical resume and replay matching, instead of being classified as a missing dependency.
- An unusable persisted successful result blocks execution durably. It does not rewrite the succeeded dispatch, attempt, or result, and it invents no compensation.
- Execution lease renewal validates owner, token, revision, expiry, and nonterminal state atomically. It never shortens a deadline.
- Transports map terminal state before cause, and they sanitize error causes.
- The daemon requires an explicit mode for migrations. Serve mode performs no implicit migration.
- The compiler writes checked output atomically in the destination directory and rejects unsafe targets.

## Security changes

This release updates two dependencies for published advisories:

- `google.golang.org/grpc` moves to 1.83.2 for CVE-2026-84445. That upgrade also raises `golang.org/x/net`, `text`, `sync`, and `sys`.
- The VS Code extension lock file moves `js-yaml` to 4.3.2 for GHSA-2883-xcg3-v3hh.

`google.golang.org/protobuf` stays at 1.36.11. The `go` directive and toolchain line are unchanged.

## Validation

Remote CI passes 15 jobs and 133 steps on the released source, including the npm audit, the Go module audit, and both container scans.

Local validation includes a 665-test race suite, coverage and benchmark measurements, PostgreSQL integration under independently offset process clocks, real Kafka commit and restart behavior, unchanged finite TLC models, and chart lint, render, and schema checks.

Three bounded end-to-end gates hold:

- A standalone Compose stack proves first-run admission and same-container restart behavior.
- A Kafka to daemon to PostgreSQL to destination fixture proves one business commit under a lost destination response, with deduplicated replay and forced Kafka redelivery.
- Remote CI proves the published source passes every job.

See the [validation records](../audits/remediation-validation.md) for commands, evidence, and limits.

## Database migration

Version 0.5.0 adds no database migration. The migrations published with v0.3.0 remain current.

Back up the database and test the restore drill before deployment. Do not run old and new daemons against one workload.

## Breaking changes

This release removes no public package or API. Compatibility imports under `compat/v03` are unchanged.

Update Go consumers with:

```bash
go get github.com/josephjohncox/effectus@v0.5.0
go mod tidy
```

Review these behavior changes before adoption:

1. A ruleset that calls an unimplemented predicate now fails at generation instead of at evaluation.
2. Unknown outcomes without a checked `SINK_GUARANTEED` contract now block instead of retrying.
3. Migrations require `--mode=migrate --database-migrations=apply`. A serve invocation no longer migrates.
4. Clients that inspected error text may see sanitized causes with unchanged status codes.

## External assumptions

These limits are unchanged from v0.4.0 and remain the operator's responsibility:

- External destinations must coordinate deduplication with their business commit and enforce fencing when required. Fencing is not a substitute for idempotency.
- The system provides no ACID transaction across an external destination and the Effectus database.
- A trusted ingress or service mesh must provide production TLS and network policy.
- Operators must provide PostgreSQL availability, backups, capacity limits, monitoring, and recovery tests.
- Kafka DLQ publication and source-offset commit can duplicate a DLQ record after a crash.
- OCI verification requires an operator-provided verifier and trust policy.

## Unvalidated paths

This release line has no evidence for these paths:

- Deployed Kubernetes, registry pull, and production recovery drills. Charts pass lint, render, and schema checks only.
- Production capacity, throughput, latency percentiles, and measured improvement.
- Destination exactly-once as a universal property. The local fixture proves one bounded scenario.
