# Effectus v0.6.0

Effectus v0.6.0 updates the build toolchain and dependencies and removes the
unused runtime from the VS Code syntax extension.
The release includes [PR #75](https://github.com/josephjohncox/effectus/pull/75)
and [PR #76](https://github.com/josephjohncox/effectus/pull/76).

## Upgrade requirement

**Building from source or consuming the Go module now requires Go 1.26 or later.**
The module pins Go 1.26.8. This replaces the Go 1.25 minimum and Go 1.25.13 pin
in v0.5.0. Both Docker builders use a digest-pinned Go 1.26.8 image, and CI uses
golangci-lint 2.13.2.

Go consumers can update with the pinned toolchain:

```bash
GOTOOLCHAIN=go1.26.8 go get github.com/josephjohncox/effectus@v0.6.0
GOTOOLCHAIN=go1.26.8 go mod tidy
```

The compiled CLI archives do not require a local Go installation.
The public Go API, protobuf wire definitions, checked execution protocol, and
database migration files are unchanged from v0.5.0. No additional database
migration is introduced by this release.

| --- | --- | --- |
| `github.com/pressly/goose/v3` | 3.26.0 | 3.28.0 |
| `github.com/jackc/pgx/v5` | 5.9.2 | 5.10.0 |
| `github.com/stretchr/testify` | 1.11.1 | 1.12.1 |
| `google.golang.org/protobuf` | 1.36.11 | 1.36.12 |
| `github.com/google/go-containerregistry` | 0.20.7 | 0.22.1 |

The resolved transitive dependencies are updated as well. The gRPC version
remains 1.83.2. Goose's new Go requirement is handled together with the compiler,
container builders, linter, and documented setup commands.

## VS Code extension

The extension now consists of declarative language configuration, grammar,
snippets, and icons. Its empty activation function and compiled entry point
have been removed, along with direct TypeScript, Node/editor type packages,
TypeScript ESLint integration, and Mocha dependencies.

The editor assets are unchanged, and the declared VS Code compatibility range
remains `^1.74.0`. Development uses Node 22 or later. Node's built-in test runner
validates the manifest and referenced assets; packaging runs those tests and
excludes development files and stale compiled output.

## Validation and release artifacts

The maintenance source passed all 15 jobs in both
[PR CI](https://github.com/josephjohncox/effectus/actions/runs/34671068749) and
[branch CI](https://github.com/josephjohncox/effectus/actions/runs/34671057432).
Those checks include PostgreSQL and Kafka integration, runtime race tests,
Go and npm vulnerability audits, container scans, Node 22 extension packaging,
formal models, chart validation, and documentation contracts.

The release workflow reruns CI for the tag before publishing. It builds CLI
archives for Linux amd64/arm64, macOS amd64/arm64, and Windows amd64, plus the
Helm chart, VSIX, and order-review source bundle. It publishes signed OCI
artifacts, checksum and completion manifests, SBOMs, and provenance.
Successful publication also requires the v0.3 compatibility imports to resolve
through the public Go proxy.

The [dependency audit](../DEPENDENCY_AUDIT.md) describes the maintenance policy.
The [runtime guarantees](../GUARANTEES.md) and [production runbook](../PRODUCTION_RUNBOOK.md)
remain the operational references. Release and CI success do not establish
deployed Kubernetes recovery or representative production capacity.
